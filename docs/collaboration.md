# Подключение второго Codex

Подготовка не создаёт второй чат автоматически. Напарник открывает свою копию
проекта в Codex и вставляет стартовое задание B. Сначала выберите один вариант.

## Подготовленный вариант для вашей команды

Создан закрытый репозиторий:
https://github.com/ramazanutegen583-pixel/fortebank-datathon

Текущий чат A работает на codex/product. Для B подготовлена codex/vision;
main содержит общую исходную версию. На компьютере напарника:

1. Войти в GitHub под своим аккаунтом и принять приглашение в репозиторий.
   Логин напарника пока не получен, приглашение ещё не отправлено.
2. Открыть PowerShell в выбранной папке для проектов и выполнить:

   ```powershell
   git clone --branch codex/vision https://github.com/ramazanutegen583-pixel/fortebank-datathon.git datathon
   ```

3. В Codex добавить полученную папку datathon как проект и открыть локальный чат.
4. Вставить:

   ```text
   Прочитай AGENTS.md, README.md и docs/prompts/agent-b.md.
   Ты агент B, выполняй B1 на ветке codex/vision.
   Конкурсные кадры и описания не передавай в Codex.
   После задачи сделай коммит и push своей ветки, обнови docs/status/agent-b.md.
   ```

Если git не установлен/не найден, напарник может дать Codex URL репозитория и
попросить клонировать ветку codex/vision в отдельную папку. Вход в аккаунт GitHub
проходит сам человек; пароли и токены в чат не отправляются.

Разрешение писать в закрытый репозиторий выдаётся конкретному аккаунту напарника.
До выдачи доступа можно начать из bundle по инструкции ниже, сохраняя локальные
коммиты. После доступа заменить файловый origin на указанный URL.

## Два компьютера без GitHub

1. Передайте напарнику файл exports/datathon-starter.bundle. Он содержит только
   отслеживаемый код, документацию и синтетические примеры. Видео/ключей в нём нет.
2. На компьютере напарника, в папке для проектов вне общей синхронизируемой рабочей
   копии, выполните:

   ```powershell
   git clone --branch codex/vision "ПУТЬ_К_ФАЙЛУ/datathon-starter.bundle" datathon
   ```

   Если Git не в PATH, укажите полный путь к git.exe. Его копия поставляется
   в составе runtime Codex, если этот runtime установлен на машине.
3. Добавьте полученную папку datathon как проект Codex. Начните локальный чат.
4. Вставьте текст из docs/prompts/agent-b.md или короткую команду:

   ```text
   Ты агент B. Прочитай AGENTS.md и docs/prompts/agent-b.md, затем выполняй B1.
   Код меняй только в своей зоне. Конкурсные видео/кадры/описания не передавай Codex.
   ```

Bundle — снимок на момент создания. Синхронизации между компьютерами сам по себе
он не создаёт. После клонирования origin указывает на файл bundle, а не на сервер.
Не пытайтесь git push в bundle. Для обмена обновлениями используйте сервер ниже
или новые bundle после коммитов.

Обмен без сервера: B делает коммиты в codex/vision, создаёт
`git bundle create ../vision-update.bundle codex/vision`, передаёт файл A.
A выполняет в своей копии
`git fetch ПУТЬ_К_ФАЙЛУ/vision-update.bundle refs/heads/codex/vision:refs/remotes/peer/vision`,
ревью, затем `git merge refs/remotes/peer/vision` на codex/product и проверки.
Если ранее эта ссылка уже получала историю B, новый bundle должен продолжать её.
Не добавлять принудительный `+` и не переписывать историю.

Чтобы передать интеграцию обратно, A создаёт
`git bundle create ../product-update.bundle codex/product`.
B делает fetch этой ветки в refs/remotes/peer/product и merge в codex/vision.

## Два компьютера с закрытым GitHub или GitLab

Удобнее после старта подключить один закрытый репозиторий. Создайте его пустым,
без автоматически созданных README/лицензии, чтобы не получить две исходные истории.
Добавьте напарника средствами выбранного сервиса.

На основном компьютере после получения настоящего URL:

```powershell
git remote add origin РЕАЛЬНЫЙ_URL_РЕПОЗИТОРИЯ
git push -u origin main
git push -u origin codex/product
git push -u origin codex/vision
```

Не выполняйте команды с текстовым placeholder вместо URL. Не создавайте второй
origin, если он уже есть: сначала проверьте `git remote -v`.
На клоне из bundle замените файловый origin:

```powershell
git remote set-url origin РЕАЛЬНЫЙ_URL_РЕПОЗИТОРИЯ
git fetch origin
git branch --set-upstream-to=origin/codex/vision codex/vision
```

Для чистого клона с сервера достаточно:
`git clone --branch codex/vision РЕАЛЬНЫЙ_URL_РЕПОЗИТОРИЯ datathon`.
После этого открыть папку в Codex и дать стартовое задание B.

## Один компьютер с двумя чатами

1. Основной чат A остаётся в текущей папке на codex/product.
2. В Codex создайте новый чат того же проекта, выберите Worktree.
3. Исходная ветка — main, содержащая общий стартовый коммит.
4. Вставьте короткое задание B выше. Пусть агент создаст codex/vision в своём
   worktree. Если ветка уже существует и не занята, он может переключиться на неё.
5. В app-managed worktree новая копия может быть detached HEAD — это нормально.
   Перед сохранением работы нужно выбрать/создать ветку, как описано в задании B.

Не открывайте два локальных чата с записью в одну и ту же папку. Worktree отделяет
файлы, но не GPU, порты и глобальные зависимости: окружения и выходные каталоги
должны быть раздельными; GPU-эксперименты запускайте по очереди.
Игнорируемые видео и веса автоматически в новый checkout не попадут.
Дайте локальной программе путь к данным отдельно, не копируйте их в Git.

## Объединение работы

- Каждый агент делает небольшие коммиты своей части и обновляет свой status-файл.
- Перед fetch/merge/pull нужно завершить коммит или осознанно сохранить свои
  правки. Не удалять изменения ради чистого дерева.
- На двух компьютерах B делает push codex/vision; A делает fetch origin,
  ревью изменений и merge origin/codex/vision в codex/product.
- На одном компьютере A видит локальную ветку codex/vision: после коммитов B
  можно ревью и merge этой ветки без сети.
- A проверяет интеграцию и переносит проверенную версию в main. В worktree,
  где main уже занят, не переключать его параллельно: обновить из основной копии.
- B перед следующим блоком получает проверенную интеграцию из main.
- Общие контракты меняет только один агент за раз. Не разрешать конфликты
  автоматическим выбором «всегда моя/всегда чужая версия».

Передача между агентами: коммит, выполненная задача, команда проверки, результат,
ограничения, следующий шаг. Изображения и описания конкурсных событий в эту
передачу не входят. Подробные локальные результаты проверяет человек.

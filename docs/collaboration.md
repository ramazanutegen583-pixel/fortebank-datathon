# Подключение второго Codex на компьютере напарника

Общий публичный репозиторий:
https://github.com/ramazanutegen583-pixel/fortebank-datathon

Ветки main, codex/product и codex/vision содержат общую стартовую версию.
Текущий чат A работает на codex/product. Второй чат запускает напарник на своём
компьютере. История этого чата ему не нужна: общий контекст сохранён в файлах.

## Шаг 1 Создать fork

Напарник входит в свой GitHub-аккаунт, открывает общий репозиторий и нажимает
Fork → Create fork. Получится собственный репозиторий вида
https://github.com/ЛОГИН_НАПАРНИКА/fortebank-datathon.
Можно оставить копирование только main: рабочую ветку создадим локально.

Публичность позволяет читать и клонировать код, но не даёт посторонним право
push в исходный репозиторий. Свой fork позволяет отправлять изменения без
приглашений и обмена паролями. Авторизацию GitHub человек проходит сам.

## Шаг 2 Подготовить рабочую папку

В PowerShell напарника, в папке для проектов, выполнить, подставив свой логин:

```powershell
git clone https://github.com/ЛОГИН_НАПАРНИКА/fortebank-datathon.git datathon
cd datathon
git remote add upstream https://github.com/ramazanutegen583-pixel/fortebank-datathon.git
git switch -c codex/vision
```

Если git не найден, напарник может попросить Codex клонировать свой fork и
создать ветку с использованием доступного локального Git. Не отправлять в чат
пароль или токен. Папка должна быть собственной рабочей копией напарника,
а не одной общей синхронизируемой папкой двух компьютеров.

Вместо выполнения команд вручную можно открыть в Codex папку для проектов и
дать ему URL своего fork вместе с командой создать отдельную рабочую копию,
настроить upstream на общий репозиторий и ветку codex/vision.

## Шаг 3 Запустить агента B

В Codex добавить клонированную папку datathon как проект и открыть локальный чат.
Вставить:

```text
Ты агент B проекта ForteBank Datathon.
Прочитай AGENTS.md, README.md и docs/prompts/agent-b.md, затем выполняй B1.
Работай на codex/vision в моей отдельной рабочей копии.
Твоя зона: vision/, evaluation/, rules/, tests/vision/.
Соблюдай contracts/README.md; общие схемы самостоятельно не меняй.
Конкурсные видео, кадры и описания не передавай в контекст Codex.
Результаты локального анализа сохраняй локально для человека.
После задачи обнови docs/status/agent-b.md, сделай коммит своей части
и push в мой fork. Подготовь pull request в исходный репозиторий,
base codex/product. В отчёте укажи проверки и ограничения.
```

Данные и веса не находятся в Git. Напарник как участник команды получает
конкурсные материалы по исходной ссылке организаторов отдельно и хранит их
локально. Путь к ним задаётся локальной программе, содержимое не выводится Codex.
Правила разрешённой AI-помощи с кодом уточняются у организаторов отдельно.

## Шаг 4 Передать изменения агенту A

После коммита B:

```powershell
git push -u origin codex/vision
```

Затем на GitHub создать pull request: base repository —
ramazanutegen583-pixel/fortebank-datathon, base branch — codex/product;
head repository — fork напарника, compare branch — codex/vision.
Codex B может подготовить PR при наличии у него авторизации и доступного инструмента.
Ссылку на PR передать человеку или в основной чат A по разрешению пользователя.

A проверяет изменения, объединяет в codex/product и проверяет общий запуск.
Проверенный результат переносит в main. Не считать успешный merge доказательством
качества распознавания: необходимы локальные испытания настоящего анализатора.

## Обновления у B

Перед следующим блоком завершить свои правки коммитом. Затем:

```powershell
git fetch upstream
git merge upstream/main
```

Если A передал согласованное изменение контракта до переноса в main, получить
указанный коммит или merge upstream/codex/product после согласования. Не выполнять
reset --hard, force push и автоматический выбор одной стороны всех конфликтов.

## Запасной перенос без GitHub

Файл exports/datathon-starter.bundle — проверяемый переносимый снимок Git,
включающий main, codex/product и codex/vision. Напарник может получить его от
владельца проекта и выполнить:

```powershell
git clone --branch codex/vision ПУТЬ_К_ФАЙЛУ/datathon-starter.bundle datathon
```

После этого открыть папку в Codex и выполнить задание B. У такого клона origin
сначала указывает на bundle, а не сервер; push в него не работает. После создания
fork выполнить `git remote set-url origin URL_СВОЕГО_FORK` и добавить upstream.
Bundle не синхронизируется автоматически и не содержит конкурсных видео/ключей.

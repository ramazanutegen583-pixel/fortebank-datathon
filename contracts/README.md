# Общий контракт v1

Это выбранная командой граница модулей. Обязательные поля внешнего API взяты
из ТЗ; HTTP-коды и формат внутренних объектов — наши проектные решения.

## Внешний API

- POST /api/v1/analyze: X-API-Key, multipart/form-data, поле file, формат .mov.
  Ответ 202 по $defs/submission из api.schema.json.
- GET /api/v1/jobs/{job_id}: X-API-Key, ответ 200 по корню api.schema.json.
- Неверный ключ: 401; неизвестное задание: 404; неверный формат: 415;
  слишком большой файл: 413. Конкретный лимит размера задаёт A с запасом
  относительно ориентировочных 29 МБ и документирует в настройках.
- processing и failed не содержат verdict или violations.
- В done только violation/no_violation. Для violation нужен непустой список
  событий; для no_violation — пустой. Каждый event содержит 1–3 JPEG base64.
- Нормативный источник показывается в UI из внутреннего sources. Чтобы не менять
  обязательную схему жюри, в API название/пункт/URL источника включаются в description.

## Анализатор

```python
from pathlib import Path
from vision.pipeline import analyze_video

result = analyze_video(video_path=Path(...), output_dir=Path(...))
```

Возвращает dict по analysis.schema.json. Функция использует локальные веса,
не делает сетевых запросов и не читает labels для принятия решений.
Создаёт output_dir при необходимости. Пути JPEG в результате — относительно
output_dir, с прямыми слешами, без абсолютных путей или выхода через `..`.
Сервер отдельно проверяет разрешённый путь и настоящий формат файлов.

Каждое событие имеет источники: название документа, URL, section (может быть null),
связь правила с видимым действием. Точные категории ещё не определены.
Описание должно относиться только к видимому и сохраняться локально.

Если результат нельзя получить технически, функция выбрасывает исключение.
Не возвращать no_violation из-за отсутствия весов, ошибки декодирования или таймаута.
Время событий — секунды от начала видео. Сервер/анализатор проверяет, что таймкоды
не выходят за длительность ролика: одного JSON Schema для этого недостаточно.

## Проверка и изменения

Схемы — JSON Schema Draft 2020-12. examples/ содержит исключительно синтетические
объекты для интеграции, включая искусственное одноцветное JPEG-изображение.
Схемы проверяют структуру и согласованность вердикта. Декодирование base64,
настоящий JPEG, существование файлов и смысл источников проверяются отдельно.

Контракт меняет A отдельным коммитом после записи предложения B в его status-файле.
Оба агента получают изменение до продолжения зависимых задач. Перед интеграцией
сверяйте examples с текущими схемами. Не добавлять новые вердикты или HTTP-маршруты
анализа внутри vision/.
